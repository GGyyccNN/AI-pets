# DSH idea：让高亮在后续对话历史中继续可见

记录日期：2026-10-13。状态：待验证的功能想法。当前优先评估现有 `dsh-answer-highlighter` 的小步扩展。

更新日期：2026-10-14（Asia/Shanghai）。增加用户要求：额外模型调用和历史标注应尽量保持模型 API 的缓存命中，避免显著增加未缓存输入与总费用。

## 用户提出的想法

在后续多轮对话中，让已经由插件标注、以及用户手动标注的语句继续带有重点标记。例如，在后续使用的历史消息中将这些语句加粗，使对话持续围绕用户关注的内容展开。重点讨论它能否帮助超长 session 的延续性。

这里将“引导后续对话”理解为：模型收到的上下文也能看见标注信号。界面上的历史高亮可以同时保留。现有插件已有自动标注，手动标注仍是此前提出的扩展方向。

## 缓存约束与方案调整

缓存稳定性是此功能的设计约束。保留“用户重点持续影响后续对话”的目标，将实现收敛为：

- 界面可对历史原文高亮或加粗；标注独立保存，已发送的模型历史不因界面操作被改写。
- 模型侧只在有新增、取消或更正时，追加少量用户重点说明；合并同一轮的多次操作，避免每轮重复追加完整清单。
- 已发送的标注说明也随历史稳定保留。不能只临时插入一轮、下一轮又移除或换位置；否则仍可能改变已缓存前缀。取消和更正以新说明表达，界面展示最新状态。
- 手动标注不需要额外模型调用；自动标注复用本地已有结果。确需辅助调用时，保持其提示词前缀稳定，单独记录用量；不同模型或不同提示词不能假定共享主对话缓存。
- 复用 host 既有压缩时机保留必要重点，压缩后建立新的稳定历史。缓存命中与效果一起评估；追加说明本身仍有输入成本。

验收应同时观察主调用缓存读取/未缓存输入、辅助调用缓存和总费用，并与无此功能的同一会话对照。暂不自定可接受的下降百分比；先测出实现的真实影响。

## 观点与价值假设

这是适合继续推进的小功能。用户阅读时的选择可以成为后续回答的关注线索，特别适用于项目约束、已经接受的决策、尚未解决的疑问。可以检验它是否减少重复解释、约束遗忘和回答偏离重点。

两种效果应分别理解：

- **界面保留标记**：帮助用户回看重点、接续思考。模型能否受到影响，取决于请求中是否包含这些信息。
- **请求包含标注信号**：给模型提供用户关注程度的提示。追加的重点说明中可以使用 Markdown 加粗，但没有保证它会提高模型对该句的权重或遵守率；明确说明“用户关注的片段”更容易理解。

自动高亮表达“模型认为值得注意”，手动高亮表达“用户选择关注”，应区分来源。两者都不自动证明该句正确或已被用户认可；存疑、反对的片段应保留用户备注，避免被误用成项目要求。

## 与超长 session 的关系

在相关历史仍位于模型输入时，标注可能帮助持续关注重要内容。这是待验证的收益。

历史一旦被截断或压缩，原句和格式可能消失。因此，超长 session 的延续性还取决于：压缩摘要是否保留必要的标注片段或用户判断，以及之后是否还能定位原文。可以先让少量用户明确选择的重点参与会话续接材料。

标注数量需要克制；过多自动重点会稀释用户重点。原文及消息身份应保留，方便取消标注、更正和追溯。

## 最小尝试

1. 在已有标注上区分自动来源与用户来源，首版优先处理少量用户标注。
2. 核对 DSH host 构造后续请求和附加上下文的入口，以追加少量用户关注片段实现模型侧提示；历史原文的突出显示由界面处理。
3. 保存原消息原文，将标注作为独立数据；编辑或取消时追加更正说明，保持已发送历史稳定。
4. 如果出现历史压缩，让续接摘要保留必要的用户重点及来源。

试验时记录实际发送的历史、缓存统计和总成本，确认追加说明在后续请求中位置与内容稳定，并核查 host 没有因功能接入而重排系统提示或工具定义。

## 如何判断有帮助

用相同长历史比较原插件与增加标注信号后的请求，观察重点约束遵守、未解决问题的延续、用户重复解释次数，以及输入成本。另行检查压缩前后重点能否保留；对话轮数本身不等同于上下文长度。

本想法的近期目标是**让用户在同一 session 中持续标出对话重点**。它可以先独立验证，再决定是否需要扩展为更完整的记忆功能。
